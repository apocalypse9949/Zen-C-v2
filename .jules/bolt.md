## 2024-05-18 - Avoid O(N^2) concatenation with quote_arg in Windows command building
**Learning:** In `src/platform/os.c`, nested loops allocating dynamically with `strcat` lead to O(N^2) execution time. Specifically, appending strings using `strcat` when iterating over argument lists becomes a bottleneck because `strcat` has to traverse the entire string to find the end before appending. For command line building, this causes ~3.15 seconds execution time for 50,000 strings compared to ~0.04s when calculating string length manually and using `memcpy` to append strings directly at the calculated offset.
**Action:** When building strings dynamically, calculate the required buffer length upfront, keep track of the current offset (`curr_pos`), and use `memcpy` at that offset instead of relying on `strcat`. Also, caching the results of functions that return newly allocated strings (like `quote_arg`) reduces redundant allocations and parsing.
