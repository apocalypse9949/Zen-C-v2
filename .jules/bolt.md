## 2026-05-11 - O(N^2) String Building in Codegen Utilities
**Learning:** `extract_call_args` and `replace_string_type` in `src/codegen/codegen_utils.c` utilized sequential `strcat` and `strncat` within `while` loops. This "Shlemiel the painter's algorithm" approach caused string manipulation to degrade to O(N^2) time complexity. In addition, an insufficient buffer allocation in `extract_call_args` (allocating `strlen(args) + 1` but appending ", " for commas) created a subtle buffer overflow risk.
**Action:** Always refactor sequential `strcat`/`strlen` loops in string building utilities to track length explicitly with `out_len` and populate via `memcpy`, reducing time complexity to O(N). Also, always calculate worst-case growth bounds (e.g., `strlen(args) * 2 + 1`) during the initial allocation when expanding formatting elements.
